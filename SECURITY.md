# Security policy

Report vulnerabilities, leaked credentials or private data found in this repository privately, using the e-mail address in `Contact.md`. Please do not open a public issue for them. Expect an acknowledgement within a few days.

The router is an offline, standard-library Python program with no network access; the main risks are private data or credentials in committed files. Committed files, including `papers/` and the full Git history, are scanned in CI with gitleaks v8.18.4 (default rules) and by `tools/publication_lint.py`. `.gitleaks.toml` does not exclude `papers/` by path (gitleaks 8.18.4 cannot combine a path with a regex in one allowlist). It skips only (1) whole lines of exactly three forms, each anchored at both ends so that extra text on the line makes it scannable again: `"key": "<citation key>"`, `"<name>sha256": "<64 hex>"` (also `"expected"`), and `"coordinate"` / `"source_coordinate"` with a paper coordinate; and (2) findings whose secret value contains the Lean namespace prefix `oai.editapproximation.` or one of three access-anchor ids found in two papers. A credential written in exactly one of the three line forms would not be detected. CI plants three random credentials that must all be detected: a GitHub-token-shaped value, a random 64-hex value assigned to `secret_key` outside `papers/`, and a token appended to a copy of a real sha256 line of a paper.

A credential that was committed is considered compromised: it is rotated or revoked first. Removing it in a new commit does not remove it from the Git history, so where history is public the maintainers may also rewrite it (a force-push after a coordinated notice); anyone holding a clone should then re-clone.
